# C-1.3 Full System Prompt 接入记录

来源：`A1/同学交接/C-v1：Full System Prompt.py`，并根据20条C版开发测试的人工评审更新。

## 使用方式

- 五类完整提示保存在 `c_full_system.py`，当前集成版本为 `C-1.3`。
- `templates.py` 保留原 A/B 模板，并提供统一选择接口；只有 C 使用交接提示。
- 当前交互界面默认运行 C，因此使用新提示。模型调用日志记录实际提示版本。
- 同学原有任务、证据、语言、安全和教学要求保留，以下改动用于适配开发副本。

## 接口适配

1. 输入统一为 `inputs.*`、`EVIDENCE` 和 `STYLE_REFERENCES`，保持现有实际请求格式。
2. Evidence 输出只需 source_id；名称、正文摘要、页码及 URL 继续由程序按卡片补齐。
3. Learning/Next 支持 need_more_information；不再把 Next 的澄清问题塞进 where_you_are。
4. Debug JSON 增加 rationale，confidence 可省略或为 null；不要求凑满三个原因。
5. GEN 增加 answer_rationale、reason 和 NEEDS_REVIEW；失败原因放 reason。题目 ID 由程序生成。
6. EXPLAIN 增加 status/reason；证据不足返回 INSUFFICIENT_EVIDENCE，歧义或候选答案错误返回 NEEDS_REVIEW，不判分。
7. 例题答案仍不传入生成提示，仅提供题型参考。官方文档标明产品/版本限制。
8. 输出示例对齐当前 Pydantic schema；调用层继续追加实际 schema 进行校验。
9. C-1.2 接入 2026-09-05 19:00 的 C-v1.1 交接 Prompt，并增加程序级 source ID 正文泄漏校验；若 ID 出现在引用字段以外，会触发一次格式修复。
10. C-1.3 根据第二轮独立评分收紧比较、诊断和出题一致性约束；代码层同步增加直接主题证据路由、task procedure 展示及学习问答证据边界检查。
10. 固定回复跟随输入语言；生成题默认标记为 `NEEDS_HUMAN_REVIEW`。

## 保持不变

- A/B 的既有提示与路由行为未改动，仍待 Prompt 组最终确认。
- DeepSeek 配置及各任务思考强度、检索、界面卡片样式均未改动。
- 本次仅做离线兼容性与界面回归检查，未执行付费模型质量评价。

新提示比之前的简版更长。速度、回答质量和 A/B/C 比较需使用真实案例另行评价；不能将格式测试通过视为教学效果已验证。
